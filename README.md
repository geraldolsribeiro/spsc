# SPSC packet batching

A C++20 single-producer/single-consumer packet pipeline. It demonstrates how
to generate packets at a target bitrate, collect them into timed byte-limited
batches, and convert every batch into fixed-size blocks.

## Architecture

```text
+----------+       SpscQueue        +----------+       +----------------+
| Producer | -- Packet ------------> | Consumer | ----> | BlockAssembler |
+----------+                         +----------+       +----------------+
  98% x 1500 B                           |              11,200 B blocks
   2% x 60 B                             v                      |
  40 Mbit/s                       batch < 65,000 B             v
                                                        consume_block()
```

There is one producer thread and one consumer thread. `SpscQueue` uses a
mutex-protected `std::deque` and a condition variable. This implementation
prioritizes clarity and safe ownership over lock-free performance.

## Producer

The producer generates packets with this distribution:

- 98% are 1500 bytes.
- 2% are 60 bytes.

The interval for every packet is calculated from its size:

```text
interval = packet_size * 8 / 40,000,000
```

Consequently, the generated byte rate is approximately 40 Mbit/s. The producer
uses `steady_clock` and `sleep_until()` with absolute target times. This avoids
accumulating scheduling and processing delays that would occur if every packet
used an independent `sleep_for()` interval.

## Batch formation

The consumer waits for the first packet using a condition variable. Once the
first packet arrives, a deadline is created:

```text
deadline = first_packet_time + T
```

Packets are moved from the queue into the current batch while the total size is
strictly less than 65,000 bytes. The batch is returned when either:

1. The next packet would make the batch reach or exceed 65,000 bytes.
2. The timeout `T` expires without another packet.
3. The queue is closed.

The strict comparison means a batch of exactly 65,000 bytes is not accepted.
The next packet is never discarded; it remains in the queue for the next batch.

## Block formation

Each batch is processed independently by `BlockAssembler`. Blocks are exactly
11,200 bytes. Packets may cross block boundaries, but blocks cannot contain
bytes from different batches:

```text
batch 1: [packet][packet][packet] -> [11,200 B] ... [tail + zero padding]
batch 2: [packet][packet]--------- -> [11,200 B] ... [tail + zero padding]
```

If a batch does not end on a block boundary, its final block is zero-padded.
The assembler is recreated for every batch, so a partial block is never carried
into the following batch.

`consume_block()` is a placeholder for the real downstream operation. It
currently computes a checksum to ensure that every block byte is read.

## Partial batches and producer pauses

If 10 packets of 1500 bytes arrive and the producer then pauses:

```text
10 x 1500 = 15,000 bytes
```

The consumer drains all 10 already-queued packets into one batch, then waits
for `T` microseconds. If no packet arrives before the timeout, the partial
batch is consumed as:

```text
Block 1: 11,200 bytes
Block 2:  3,800 bytes of data + 7,400 bytes of zero padding
```

A producer pause leaves the queue open, so the consumer waits until `T`.
During shutdown, the producer closes the queue and wakes the consumer, which
drains remaining packets without waiting for the timeout.

## Statistics

Every 500 ms the program reports:

- Measured produced bitrate.
- Measured consumed bitrate.
- Produced and consumed packet counts.
- Number of completed batches.
- Batch fill ratio.

The fill ratio is batch utilization, not block utilization:

```text
fill_ratio = consumed_bytes / (batch_count * 65,000)
```

Because batches are timeout-limited, a short timeout usually produces smaller
batches. A rough timeout needed to fill a batch at bitrate `R` is:

```text
T = 65,000 * 8 / R
```

At 40 Mbit/s this is approximately 13,000 microseconds. A practical value such
as 15,000 microseconds allows scheduling margin.

## Build and run

```sh
make
./spsc_packets [timeout_microseconds] [run_seconds]
```

Examples:

```sh
./spsc_packets          # T=1000 us, run for 5 seconds
./spsc_packets 13000 5  # T=13000 us, run for 5 seconds
make run                # Runs the default demonstration
```

The `Makefile` builds with C++20, warnings enabled, optimization, and pthread
support. Use `make clean` to remove the executable.

## Shutdown and ownership

`std::jthread` provides automatic joining and cooperative stop tokens. The main
thread first stops and joins the producer. The producer closes the queue after
its final packet. The consumer then drains queued packets, pads the final block
of its current batch, and exits. Finally, the main thread requests consumer
stop and joins it.

Packets are moved into and out of the queue, avoiding unnecessary payload
copies. `std::span` is used when a function only needs a non-owning view of
packets or block bytes. Atomic counters are used because worker threads update
them while the reporting thread reads them.
